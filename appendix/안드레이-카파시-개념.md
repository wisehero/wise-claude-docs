# 안드레이 카파시의 LLM 개념 사전

> **난이도**: 전체 | **선행 문서**: 없음 | **최초 작성**: 2026-04-25 | **마지막 수정**: 2026-04-25
>
> 전 OpenAI 창립 멤버이자 Tesla AI Director였던 Andrej Karpathy(현 Eureka Labs)가 LLM 시대에 정의·확산시킨 개념들을 1차 출처와 함께 정리한다.

---

## 1. 인물 배경

Andrej Karpathy는 OpenAI 창립 멤버로 합류했다가 Tesla로 옮겨 Autopilot팀 AI Director를 맡았고, 다시 OpenAI로 돌아와 GPT-4 개발에 참여했다. 2024년 교육 스타트업 Eureka Labs를 창업했다. nanoGPT, micrograd 같은 교육용 코드 공개로도 유명하다.

LLM 시대에 그가 만든 용어들 — Software 2.0, Vibe Coding, Context Engineering, LLM OS — 은 이제 업계 공용어가 됐다. 이 문서는 각 개념의 1차 출처와 원문 정의를 추적해 정리한다.

## 2. Software 1.0 / 2.0 / 3.0

### Software 2.0 (2017)

**원문**: "The 'classical stack' of Software 1.0 is what we're all familiar with — it is written in languages such as Python, C++, etc. ... **Software 2.0 is written in much more abstract, human unfriendly language, such as the weights of a neural network**."

**핵심 주장**: 신경망은 단순히 분류기 도구가 아니라 소프트웨어 패러다임 자체의 변화다. 명시적 코드를 작성하기 어려운 영역(비전, 음성, 번역)이 데이터 수집 가능한 영역으로 이동하면서 Software 2.0으로 마이그레이션 중이다.

출처: [Software 2.0 — karpathy.medium.com (2017-11-11)](https://karpathy.medium.com/software-2-0-a64152b37c35)

### Software 3.0 (2025)

**정의**: 자연어로 LLM을 프로그래밍하는 시대. 코드가 아니라 영어로 컴퓨터를 제어한다.

**핵심 주장**: 1.0(전통 코딩) → 2.0(신경망 학습) → 3.0(자연어 프롬프트). 비개발자도 의도를 표현해 시스템을 만든다. 단, 각 패러다임은 사라지지 않고 stack으로 누적된다.

출처: [Latent Space — Software 3.0 (2025)](https://www.latent.space/p/s3)

## 3. Vibe Coding

**원문 트윗 (2025-02-02)**:

> "There's a new kind of coding I call 'vibe coding', where you **fully give in to the vibes, embrace exponentials, and forget that the code even exists**."

Cursor Composer + Sonnet 조합이 충분히 좋아져서, 코드 자체에 신경 쓰지 않고 자연어로만 의도를 전달하는 방식. 그가 직접 MenuGen(레스토랑 메뉴 사진을 분석하는 앱)을 웹 개발 경험 없이 vibe coding으로 만든 사례를 블로그에 기록했다. 같은 글에서 환각, 환경변수 오류 등 한계도 솔직히 적었다.

출처: [@karpathy 트윗 (2025-02-02)](https://x.com/karpathy/status/1886192184808149383), [Vibe Coding MenuGen (2025-04-27)](https://karpathy.bearblog.dev/vibe-coding-menugen/)

### Agentic Engineering — 1년 후의 자기 회고

2026년 초, Karpathy는 vibe coding을 "passé(구식)"라고 선언하며 새 용어를 제시했다.

> "You are not writing the code directly 99% of the time, you are orchestrating agents who do and acting as oversight — 'engineering' to emphasize that there is an art & science and expertise to it."

핵심은 vibe라는 단어가 가진 "느낌대로" 뉘앙스가 책임 있는 엔지니어링을 가리지 않게 하려는 의도다. 에이전트 신뢰성이 올라간 만큼, 개발자는 코드 작성자가 아닌 에이전트 감독자(oversight)로 역할이 바뀌었다.

출처: [The New Stack — Vibe coding is passé](https://thenewstack.io/vibe-coding-is-passe/)

## 4. Context Engineering

**원문 트윗**:

> "People associate prompts with short task descriptions. In every industrial-strength LLM app, **context engineering is the delicate art and science of filling the context window with just the right information**."

Karpathy의 비유: **LLM은 CPU, 컨텍스트 윈도우는 RAM**이다. 그래서 RAM에 무엇을 채울지 — RAG로 가져온 외부 지식, 메모리, 도구 정의, few-shot 예시 — 를 설계하는 일이 핵심이고, 이를 prompt engineering보다 한 단계 위 추상으로 부르자는 제안이다.

이 개념은 Claude Code의 CLAUDE.md, 스킬, MCP 서버 같은 메커니즘이 왜 존재하는지 설명하는 사고 틀로도 자주 인용된다.

출처: [@karpathy 트윗](https://x.com/karpathy/status/1937902205765607626)

## 5. LLM as Operating System

**원문 트윗 (2023-09-28)**:

> "**LLMs not as a chatbot, but the kernel process of a new Operating System.**"

LLM을 채팅 인터페이스로만 보는 것은 초기 컴퓨터를 계산기로 본 것과 같다는 주장. 그가 그린 LLM OS의 구성 요소:

- 멀티모달 입출력 (텍스트·오디오·비전)
- 코드 인터프리터 (계산·실행)
- 브라우저 (웹 접근)
- 임베딩 DB (벡터 저장소)
- 메모리 저장/검색

이 비유는 이후 "에이전트", "tool use", "memory", MCP 같은 구체적 메커니즘들이 등장하면서 사후적으로 정확했음이 입증됐다.

출처: [@karpathy 트윗 (2023-09-28)](https://x.com/karpathy/status/1707437820045062561)

## 6. Hallucination is a Feature, Not a Bug

**원문 트윗 (2023-12-08)**:

> "**Hallucination is all LLMs do. They are dream machines.** We direct their dreams with prompts."

핵심 주장: LLM은 본질적으로 생성 시스템이고, 사실과 일치하지 않을 때만 "환각"으로 레이블될 뿐, 동작 메커니즘 자체는 동일하다. RAG, 검증 체인, 도구 사용으로 정확도를 올릴 수는 있지만, 생성 본질은 변하지 않는다.

이 관점은 "환각을 없애야 한다"는 일반적 프레임을 뒤집어, "환각을 어디로 향하게 할지(direct)" 설계하는 것이 진짜 문제라는 시각을 제시한다.

출처: [@karpathy 트윗 (2023-12-08)](https://x.com/karpathy/status/1733299213503787018)

## 7. Decade of Agents — "Year of Agents" 회의론

2025년 10월 Dwarkesh Patel 인터뷰에서 한 발언으로 화제가 됐다.

> "Not a year of agents, but a **decade of agents**."

핵심 주장:

- 현재 에이전트는 "그냥 작동하지 않는다(just don't work)". 충분한 지능, 멀티모달성, 학습·메모리 능력이 부족하다.
- 단일 돌파구(breakthrough)로 해결되지 않을 것이고, 향후 10년에 걸친 점진적 개선이 필요하다.
- human-in-the-loop 모델이 한동안 유지될 것이다.

이 관점은 2025-2026년의 "에이전트 거품" 논쟁에서 신중론 진영의 대표 인용으로 자리잡았다. Boris Cherny의 "코딩은 해결됐다" 발언과 정면으로 대비되는 지점이라 함께 읽으면 흥미롭다.

출처: [Dwarkesh Patel — Andrej Karpathy 인터뷰 (2025-10)](https://www.dwarkesh.com/p/andrej-karpathy)

## 8. RLHF는 "거의 RL이 아니다"

**원문 트윗 (2024-08-07)**:

> "**RLHF is just barely RL.**"

핵심 주장:

- AlphaGo 같은 폐쇄 환경 RL과 달리, "기사 요약" "농담 만들기" 같은 작업은 보상 함수를 명확히 정의할 수 없다.
- 인간 평가는 게이밍(reward hacking) 가능하고 노이즈가 크다.
- **Generator-Discriminator Gap**: 사람이 좋은 답을 처음부터 쓰는 건 어렵지만, 후보 중에서 좋은 답을 고르는 건 쉽다 → RLHF가 SFT보다 확장 가능한 이유.

같은 시기에 그가 LLM의 한계를 표현한 두 비유:

- **Swiss Cheese**: LLM은 어떤 영역에선 잘 작동하지만 무작위로 구멍 뚫린 곳이 있다.
- **Summoning Ghosts**: "We're not evolving animals. We're summoning ghosts." — 생물학적 지능을 진화시키는 것이 아니라 텍스트 모방으로 유령을 소환하는 작업이라는 비유.

출처: [@karpathy 트윗 (2024-08-07)](https://x.com/karpathy/status/1821277264996352246)

## 9. 교육 철학 — "What I cannot create, I do not understand"

Feynman 인용을 자기 교육 작업의 모토로 삼는다. nanoGPT, micrograd 같은 프로젝트의 공통점:

- **micrograd**: 스칼라 역전파를 ~100줄로 구현
- **nanoGPT**: GPT 학습용 최소 레퍼런스 구현
- **microGPT** (2026-02): 외부 의존성 0, 200줄 순수 Python으로 GPT 구현

핵심 원칙:

- "Intuition before formalism, construction before consumption"
- 추상화된 라이브러리를 쓰기 전에 직접 구현해보라
- "Hacker's Guide" 스타일 — 수식 유도보다 코드와 직관

이 철학은 Claude Code/Cowork 같은 도구를 쓰는 입장에도 적용된다 — 한 번은 모델/하네스가 어떻게 동작하는지 직접 들여다본 뒤에 도구를 신뢰하라.

출처: [microGPT (2026-02-12)](http://karpathy.github.io/2026/02/12/microgpt/), [GitHub karpathy](https://github.com/karpathy)

## 10. 핵심 정리

| 개념 | 한 줄 정의 | 등장 |
|---|---|---|
| Software 2.0 | 명시적 코드 대신 신경망 가중치로 표현되는 소프트웨어 | 2017 |
| Software 3.0 | 자연어로 LLM을 프로그래밍하는 시대 | 2025 |
| Vibe Coding | 코드 존재를 잊고 자연어로만 의도를 전달하는 코딩 | 2025-02 |
| Agentic Engineering | 코드 작성자가 아닌 에이전트 감독자로의 역할 전환 | 2026 초 |
| Context Engineering | 프롬프트가 아닌 컨텍스트 윈도우 전체 설계의 기예 | 2025 |
| LLM OS | LLM을 새 운영체제의 커널 프로세스로 보는 비유 | 2023-09 |
| Hallucination as feature | 환각은 버그가 아니라 LLM 작동의 본질 | 2023-12 |
| Decade of Agents | 에이전트 시대는 1년이 아니라 10년 단위 | 2025-10 |
| RLHF is barely RL | RLHF는 진정한 RL이 아니며 보상 함수 정의가 모호 | 2024-08 |

이 개념들은 Anthropic 공식 문서가 다루지 않는 *이론적 배경*을 채워준다. Boris Cherny의 실용적 사상(`보리스-체르니-인사이트.md`)과 함께 읽으면 도구의 동작 방식과 한계를 더 입체적으로 이해할 수 있다.
