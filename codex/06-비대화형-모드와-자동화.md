> Codex CLI의 비대화형 실행 방법과 CI/CD 파이프라인 통합 패턴을 다룬다.

---

## 들어가며

Codex CLI의 강점 중 하나는 사용자 입력 없이 완전히 자동화된 방식으로 실행할 수 있다는 점이다. `codex exec` 서브명령어가 이 역할을 한다. CI/CD 파이프라인, cron 작업, 스크립트 등에서 에이전트를 실행하고 결과를 받아올 수 있다.

---

## 1. codex exec — 비대화형 실행

`codex exec`는 작업을 완료하고 자동으로 종료하는 단발성 실행 모드다.

```bash
codex exec "작업 설명"
```

**동작 방식**:
1. 작업 설명을 에이전트에 전달
2. 에이전트가 작업 완료까지 자율적으로 실행
3. 완료 후 프로세스 종료

비대화형 실행에 적합하지만, 어떤 승인 정책과 샌드박스로 돌릴지는 명시해 두는 편이 안전하다.

```bash
# `--full-auto` 프리셋으로 실행
codex exec "모든 TODO 주석을 GitHub Issue 형식으로 변환해줘" --full-auto

# 또는 승인 정책과 샌드박스를 명시적으로 설정
codex exec "작업" \
  --ask-for-approval on-request \
  --sandbox workspace-write
```

## 2. 출력 제어

### 표준 출력과 표준 에러 분리

`codex exec`는 진행 상황을 stderr, 최종 결과를 stdout으로 출력한다.

```bash
# 최종 결과만 파일로 저장
codex exec "코드베이스 분석 후 요약" --full-auto > result.txt

# 진행 상황 숨기고 결과만 출력
codex exec "작업" --full-auto 2>/dev/null
```

### 구조화된 JSON 출력

`--output-schema` 플래그로 **JSON 스키마 파일 경로**를 지정하면 에이전트가 결과를 구조화된 형태로 반환한다. 파이프라인에서 결과를 파싱할 때 유용하다.

```bash
cat > schema.json <<'EOF'
{
  "type": "object",
  "properties": {
    "vulnerabilities": {
      "type": "array",
      "items": {
        "type": "object",
        "properties": {
          "severity": {"type": "string"},
          "file": {"type": "string"},
          "line": {"type": "number"},
          "description": {"type": "string"}
        }
      }
    },
    "summary": {"type": "string"}
  }
}
EOF

codex exec "이 코드베이스에서 발견된 보안 취약점을 분석해줘" \
  --full-auto \
  --output-schema schema.json
```

결과를 `jq`로 파싱한다.

```bash
result=$(codex exec "분석" --full-auto --output-schema schema.json 2>/dev/null)
echo "$result" | jq '.vulnerabilities[] | select(.severity == "critical")'
```

## 3. GitHub Actions 연동

### 기본 워크플로우

```yaml
name: Codex 자동화
on:
  workflow_dispatch:
    inputs:
      task:
        description: "Codex에게 실행할 작업"
        required: true

jobs:
  codex:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          token: ${{ secrets.GITHUB_TOKEN }}

      - uses: actions/setup-node@v4
        with:
          node-version: 22

      - name: Codex CLI 설치
        run: npm install -g @openai/codex

      - name: Codex 실행
        env:
          OPENAI_API_KEY: ${{ secrets.OPENAI_API_KEY }}
        run: |
          codex exec "${{ inputs.task }}" --full-auto

      - name: 변경사항 커밋
        run: |
          git config user.name "Codex Bot"
          git config user.email "codex@github-actions"
          git add .
          git diff --staged --quiet || git commit -m "chore: Codex 자동화 적용"
          git push
```

### 정기 실행 워크플로우 — 코드 품질 자동 관리

```yaml
name: 주간 코드 품질 개선
on:
  schedule:
    - cron: "0 9 * * 1"  # 매주 월요일 오전 9시

jobs:
  improve:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22

      - run: npm install -g @openai/codex

      - name: 사용하지 않는 import 정리
        env:
          OPENAI_API_KEY: ${{ secrets.OPENAI_API_KEY }}
        run: |
          codex exec \
            "src/ 디렉터리에서 사용하지 않는 import를 모두 제거해줘. 
             각 파일의 테스트도 함께 확인해서 누락된 import가 없도록 해줘." \
            --full-auto

      - name: PR 생성
        uses: peter-evans/create-pull-request@v6
        with:
          title: "chore: 사용하지 않는 import 정리 (Codex 자동)"
          body: "Codex CLI가 자동으로 사용하지 않는 import를 정리했습니다."
          branch: chore/codex-cleanup-${{ github.run_number }}
```

### PR 리뷰 자동화

```yaml
name: PR 자동 리뷰
on:
  pull_request:
    types: [opened, synchronize]

jobs:
  review:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          ref: ${{ github.head_ref }}

      - uses: actions/setup-node@v4
        with:
          node-version: 22

      - run: npm install -g @openai/codex

      - name: Codex PR 리뷰
        env:
          OPENAI_API_KEY: ${{ secrets.OPENAI_API_KEY }}
        run: |
          DIFF=$(git diff origin/main...HEAD)
          codex exec \
            "다음 PR 변경사항을 리뷰해줘. 보안 취약점, 성능 문제, 테스트 누락을 중점으로 확인해.
             
             변경사항:
             $DIFF" \
            --full-auto \
            --output-schema '{"type":"object","properties":{"review":{"type":"string"}}}' \
            2>/dev/null | jq -r '.review' > review.txt

      - name: 리뷰 코멘트 게시
        uses: actions/github-script@v7
        with:
          script: |
            const fs = require('fs');
            const review = fs.readFileSync('review.txt', 'utf8');
            github.rest.issues.createComment({
              owner: context.repo.owner,
              repo: context.repo.repo,
              issue_number: context.issue.number,
              body: `## Codex 자동 리뷰\n\n${review}`
            });
```

## 4. 로컬 자동화 스크립트

### Makefile 통합

```makefile
.PHONY: codex-test codex-docs codex-fix

# 테스트 커버리지가 낮은 파일에 테스트 추가
codex-test:
	codex exec \
		"테스트 커버리지 보고서를 분석해서 커버리지가 60% 미만인 파일에 \
		 JUnit 5 단위 테스트를 추가해줘." \
		--full-auto

# API 문서 자동 생성
codex-docs:
	codex exec \
		"src/presentation/ 디렉터리의 모든 컨트롤러를 분석해서 \
		 Swagger @Operation 어노테이션을 추가해줘." \
		--full-auto

# 린터 오류 자동 수정
codex-fix:
	npm run lint 2>&1 | codex exec \
		"다음 ESLint 오류를 수정해줘: $(cat -)" \
		--full-auto
```

### 반복 작업 배치 처리

여러 파일에 같은 변환을 적용할 때 파일 목록을 전달한다.

```bash
#!/bin/bash
# 오래된 콜백 패턴을 async/await로 변환

FILES=$(find src -name "*.js" -newer .last-conversion)

if [ -z "$FILES" ]; then
  echo "변환할 파일 없음"
  exit 0
fi

codex exec \
  "다음 파일들의 콜백 패턴을 async/await으로 변환해줘. 
   각 파일의 기존 테스트가 모두 통과해야 해.
   
   파일 목록:
   $FILES" \
  --full-auto

touch .last-conversion
```

## 5. 비대화형 모드 사용 시 주의사항

**git 저장소 필수**

git 저장소에서 실행하는 편이 훨씬 안전하다. 변경 추적과 복구가 쉬워지기 때문이다. 필요하면 `--skip-git-repo-check`로 체크를 건너뛸 수 있지만, 자동화에서는 신중하게 써야 한다.

```bash
# git 초기화 후 실행
git init && git add . && git commit -m "init"
codex exec "작업" --full-auto
```

**작업 범위를 구체적으로 지정**

비대화형 모드에서는 중간에 방향을 수정할 수 없다. 작업 설명에 대상 디렉터리, 제약조건, 금지 사항을 명시한다.

```bash
# 나쁜 예 — 범위가 모호하다
codex exec "코드를 개선해줘" --full-auto

# 좋은 예 — 범위와 제약조건이 명확하다
codex exec \
  "src/order/ 디렉터리의 Java 파일에서만 사용하지 않는 private 메서드를 제거해줘.
   public API는 변경하지 않고, 각 파일의 기존 테스트가 모두 통과해야 해.
   src/payment/ 디렉터리는 건드리지 않는다." \
  --full-auto
```

## 6. 핵심 정리

- `codex exec "작업" --full-auto`로 사용자 입력 없이 작업을 자동 실행한다.
- `--output-schema`는 JSON 스키마 파일 경로를 받아 구조화된 출력을 유도한다.
- GitHub Actions에서 `OPENAI_API_KEY` 시크릿으로 인증하고 주기적 자동화를 구성한다.
- 비대화형 모드에서는 작업 설명에 대상 범위와 제약조건을 명시해야 한다.
- git 저장소에서 실행하는 편이 안전하며, 필요 시에만 repo 체크를 건너뛴다.
