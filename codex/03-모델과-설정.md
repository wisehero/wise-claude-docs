> Codex CLI에서 사용 가능한 모델과 설정 파일 구조를 다룬다.

---

## 들어가며

Codex CLI는 OpenAI의 여러 모델을 지원한다. 어떤 모델을 선택하느냐에 따라 속도, 비용, 코딩 성능이 달라진다. 설정 파일(`~/.codex/config.toml`)을 통해 기본 모델, 승인 정책, 샌드박스 수준 등을 프리셋으로 저장해두면 매번 플래그를 입력하지 않아도 된다.

---

## 1. 지원 모델

### 주요 모델 비교

| 모델 | 특징 | 추천 용도 |
|------|------|-----------|
| `gpt-5.4` | 강력한 추론과 도구 사용, 전문 업무용 플래그십 | 복잡한 아키텍처 설계, 알고리즘 구현 |
| `gpt-5.4-mini` | 빠르고 효율적인 소형 모델 | 일상적인 코딩 작업, 반복 자동화 |
| `gpt-5.3-codex` | 복잡한 소프트웨어 엔지니어링 특화 | 장시간 에이전트 태스크, 대규모 리팩토링 |
| `gpt-5.3-codex-spark` | 실시간 코딩 반복 최적화, 텍스트 전용 리서치 프리뷰 | 빠른 피드백이 필요한 작업 |

### 모델 선택 기준

**`gpt-5.4` 선택 시나리오**
- 복잡한 버그의 원인 추론
- 새 시스템 아키텍처 설계
- 정확도가 속도보다 중요한 작업
- 기본 시작점으로 추천

**`gpt-5.4-mini` 선택 시나리오**
- 반복적인 코드 스타일 통일
- 간단한 리팩토링
- 문서 자동 생성
- 빠른 응답이 필요하거나 비용을 절감하려는 경우

**`gpt-5.3-codex` 선택 시나리오**
- 여러 파일에 걸친 대규모 변경
- 장시간 실행되는 에이전트 워크플로우
- full-auto 모드에서 복잡한 자율 작업

**`gpt-5.3-codex-spark` 선택 시나리오**
- 코드 반복을 빠르게 실험하는 경우
- 실시간에 가까운 응답이 필요한 작업

### 모델 변경 방법

**실행 시 지정**

```bash
codex -m gpt-5.4
codex --model gpt-5.4-mini
```

**세션 중 전환**

```
/model
```

`/model` 명령어를 입력하면 사용 가능한 모델 목록이 나타나고, 선택하면 이후 대화부터 해당 모델이 사용된다.

**설정 파일에 기본값 저장**

```toml
model = "gpt-5.4-mini"
```

## 2. 설정 파일 구조

### 파일 위치

설정 파일은 **TOML 형식**이다.

```
~/.codex/config.toml          # 전역 설정 (모든 프로젝트에 적용)
.codex/config.toml            # 프로젝트별 설정 (해당 디렉터리에서 실행 시 적용)
/etc/codex/config.toml        # 시스템 레벨 설정 (Unix)
```

**우선순위**: CLI 플래그 > 프로필 > 프로젝트 설정 > 전역 설정 > 시스템 설정 > 기본값

### 전체 설정 항목

```toml
# 기본 모델
model = "gpt-5.4"

# 승인 정책: untrusted | on-request | never
approval_policy = "untrusted"

# 샌드박스 수준: read-only | workspace-write | danger-full-access
sandbox_mode = "workspace-write"

# 웹 검색 모드
web_search = "live"

# 추론 노력 수준
model_reasoning_effort = "medium"

# 통신 스타일
personality = "pragmatic"

# 로그 디렉터리
log_dir = "~/.codex/logs"

# 기능 활성화/비활성화
[features]
# 실험적 기능 토글

# 환경 변수 제어
[shell_environment_policy]
# 셸 환경 변수 전달 정책

# Windows 샌드박스 설정 (WSL2 환경)
[windows]
# Windows 전용 설정
```

### 주요 설정 설명

**`approval_policy`**

세션 시작 시 기본 승인 정책을 설정한다. 개발 중에는 `untrusted`, 자동화 환경에서는 `on-request` 또는 `never`를 검토한다.

```toml
approval_policy = "on-request"
```

**`sandbox_mode`**

에이전트가 접근할 수 있는 범위를 설정한다.

| 값 | 설명 |
|----|------|
| `read-only` | 파일시스템 읽기만 허용 |
| `workspace-write` | 작업 디렉터리 읽기/쓰기 허용 |
| `danger-full-access` | 제한 없음 (위험 — 필요한 경우에만 사용) |

## 3. 환경 변수

설정 파일 대신 환경 변수로 제어할 수 있다. CI/CD에서 특히 유용하다.

| 환경 변수 | 설명 |
|-----------|------|
| `OPENAI_API_KEY` | API 인증 키 |

```bash
export OPENAI_API_KEY="sk-..."
```

## 4. 상황별 설정 예시

### 개발 환경 — 개인 전역 설정

```toml
# ~/.codex/config.toml
model = "gpt-5.4"
approval_policy = "untrusted"
sandbox_mode = "workspace-write"
```

### CI/CD 환경 — 프로젝트별 설정

```toml
# .codex/config.toml
model = "gpt-5.4-mini"
approval_policy = "on-request"
sandbox_mode = "workspace-write"
```

```yaml
# .github/workflows/codex.yml
env:
  OPENAI_API_KEY: ${{ secrets.OPENAI_API_KEY }}
```

### 복잡한 작업 — 실행 시 모델 지정

```bash
codex -m gpt-5.4
```

---

## 5. 핵심 정리

- 일상 작업에는 `gpt-5.4-mini`, 복잡한 추론에는 `gpt-5.4`, 대규모 에이전트 작업에는 `gpt-5.3-codex`를 사용한다.
- 설정 파일은 **TOML 형식**이며 경로는 `~/.codex/config.toml`이다. (`.yaml` 아님)
- 모델 지정 플래그는 `-m` 또는 `--model`이다.
- `approval_policy`에는 `untrusted`, `on-request`, `never` 중 하나를 지정한다.
- `sandbox_mode`에 `read-only`, `workspace-write`, `danger-full-access` 중 하나를 지정한다.
