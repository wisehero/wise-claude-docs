## 팀 도입을 고려해야 할 때

모든 팀에 Cowork가 필요한 것은 아니다. 아래 신호가 두 가지 이상 해당된다면 도입을 검토할 만하다.

### 도입 신호

- **반복적인 문서 작업이 많다** — 매주 같은 형식의 보고서를 만들고, 데이터를 복사·붙여넣기하고, 파일 이름을 일일이 바꾸는 작업이 반복된다
- **데이터 추출·변환에 시간을 쏟는다** — CSV에서 Excel로, PDF에서 텍스트로, 여러 파일에서 핵심 정보를 뽑아내는 작업이 잦다
- **보고서 생성 주기가 짧다** — 일간, 주간, 월간 보고서를 수작업으로 만들고 있다
- **파일 관리 부담이 크다** — 수백, 수천 개의 파일을 분류하고 정리하는 데 인력을 투입하고 있다
- **정형 업무에 고급 인력이 묶여 있다** — 분석가가 분석 대신 데이터 정리에 하루의 절반을 쓰고 있다

### ROI 사례

Cowork 도입 효과를 수치로 보면 이해가 빠르다.

| 작업 | 기존 소요 시간 | Cowork 소요 시간 | 절감 효과 |
|------|---------------|-----------------|-----------|
| 611개 파일 분류·정리 | 반나절 (4시간) | 2분 | 99% 절감 |
| 월간 실적 보고서 작성 | 하루 (8시간) | 1시간 | 87% 절감 |
| 50개 PDF에서 핵심 조건 추출 | 2시간 | 10분 | 92% 절감 |
| 주간 데이터 종합 리포트 | 3시간 | 20분 | 89% 절감 |

절감된 시간을 분석, 기획, 의사결정 같은 고부가가치 업무에 재배분할 수 있다. 단순 반복 업무 비중이 높은 팀일수록 ROI가 크다.

## 구독 플랜 선택

Cowork를 사용하려면 Pro 이상의 구독이 필요하다. 팀 규모와 사용 패턴에 따라 적합한 플랜이 다르다.

### 플랜 비교표

| 플랜 | 가격 | Cowork | 사용량 | 적합한 팀 |
|------|------|--------|--------|-----------|
| **Pro** | $20/월 | ✅ | 기본 | 개인 또는 소규모 시범 운영 |
| **Max 5x** | $100/월 | ✅ | Pro의 5배 | 일반 업무 팀 (하루 2-3시간 사용) |
| **Max 20x** | $200/월 | ✅ | Pro의 20배 | 헤비 유저, 전일 사용 |
| **Team Standard** | $20/seat/월 | ❌ | 기본 | Chat만 필요한 팀 |
| **Team Premium** | $100/seat/월 | ✅ | 5배 | Cowork가 필요한 팀 |
| **Enterprise** | 문의 | ✅ | 커스텀 | 대규모 조직 |

### 개인 플랜 vs 팀 플랜

개인 플랜(Pro, Max)은 각자 구독하는 방식이다. 팀 플랜(Team, Enterprise)은 관리자가 중앙에서 구독을 관리한다.

| 항목 | 개인 플랜 (Pro/Max) | 팀 플랜 (Team/Enterprise) |
|------|-------------------|-------------------------|
| 결제 | 개인 카드 | 회사 카드, 중앙 결제 |
| 사용자 관리 | 각자 관리 | 관리자가 추가/제거 |
| 권한 설정 | 불가 | 역할별 기능 제한 가능 |
| 사용량 모니터링 | 불가 | 대시보드, Analytics API |
| 지출 한도 | 불가 | 그룹별 한도 설정 가능 |

5명 이하의 소규모 시범 운영이라면 개인 Pro 플랜으로 시작해도 되지만, 본격적인 팀 도입에는 Team 이상의 플랜이 적합하다.

### 팀 플랜 핵심 사항

- **최소 5석(seat)**: Team 플랜은 최소 5명부터 시작한다
- **혼합 구성 가능**: Standard($20)와 Premium($100)을 혼합할 수 있다. Cowork가 필요한 사람만 Premium으로 지정하면 비용을 절약할 수 있다
- **Enterprise**: seat 비용 + 토큰 사용량(API 과금) 구조. 50만 토큰 컨텍스트 윈도우(한 번에 처리할 수 있는 정보량이 더 크다), 전담 지원 포함

### 플랜 선택 의사결정 흐름

```
시범 운영 (5명 이하)?
  → 개인 Pro 플랜으로 시작

팀 전체 도입 (5명 이상)?
  → Chat만 필요한 인원 → Team Standard ($20/seat)
  → Cowork 필요한 인원 → Team Premium ($100/seat)

대규모 조직 (50명 이상)?
  → Enterprise (맞춤 견적)
```

## RBAC (역할 기반 접근 제어)

RBAC(Role-Based Access Control)는 "누가 어떤 기능을 쓸 수 있는지"를 역할 단위로 관리하는 체계다. Team 플랜 이상에서 사용할 수 있다.

### 기본 구조

```
조직
├── 그룹: 마케팅팀
│   ├── 역할: Cowork + Gmail 커넥터
│   └── 구성원: 김마케터, 이디자이너, 박콘텐츠
│
├── 그룹: 재무팀
│   ├── 역할: Cowork + FactSet + Excel 스킬
│   └── 구성원: 최재무, 정회계
│
└── 그룹: 운영팀
    ├── 역할: Cowork (기본 기능만)
    └── 구성원: 한운영, 송총무
```

### 그룹 관리 방법

사용자를 그룹으로 묶는 방법은 두 가지다.

| 방법 | 설명 | 적합한 상황 |
|------|------|------------|
| **수동 지정** | Admin Console에서 직접 사용자를 그룹에 추가 | 소규모 팀, 유연한 구성 필요 |
| **SCIM 연동** | 회사 디렉터리(Okta, Azure AD 등)와 자동 동기화 | 대규모 조직, 기존 IAM 체계 활용 |

SCIM을 연동하면 회사의 조직도가 바뀔 때 Cowork의 그룹도 자동으로 갱신된다. 사람이 팀을 이동하면 권한도 자동으로 바뀐다.

### 역할 설정 예시

부서별로 필요한 기능만 허용하면 보안과 비용을 동시에 관리할 수 있다.

| 부서 | 허용 기능 | 제한 기능 |
|------|-----------|-----------|
| 마케팅팀 | Cowork, Gmail 커넥터, Google Drive | Computer Use, 예약 작업 |
| 재무팀 | Cowork, FactSet, Excel 스킬 | Gmail, Computer Use |
| 운영팀 | Cowork 기본 (파일 작업만) | 모든 커넥터, Computer Use |
| IT팀 | 모든 기능 (관리자) | 제한 없음 |

### Cowork 선택적 배포

모든 부서에 동시에 Cowork를 배포할 필요는 없다. RBAC를 활용하면 특정 부서에만 Cowork를 켜고, 나머지 부서는 Chat만 사용하게 할 수 있다.

```
Phase 1: IT팀만 Cowork 활성화 (시범)
Phase 2: 마케팅팀 + 재무팀 추가
Phase 3: 전 부서 활성화
```

## 예산 관리 — 그룹 지출 한도

Team/Enterprise 플랜에서는 그룹별 지출 한도를 설정할 수 있다. 예상치 못한 비용 폭증을 막는 안전장치다.

### 지출 한도 작동 방식

1. Admin Console에서 그룹별 월간 지출 한도를 설정한다
2. 해당 그룹의 사용량이 한도에 도달하면 사용이 자동 중단된다
3. 다음 결제 주기가 시작되면 사용량이 초기화된다
4. 한도를 늘리거나 줄이는 것은 관리자가 언제든 가능하다

### 설정 예시

| 그룹 | 월간 한도 | 근거 |
|------|-----------|------|
| 마케팅팀 (5명) | $500/월 | 일간 보고서 + 주간 분석 = 약 $400 예상, 여유분 포함 |
| 재무팀 (3명) | $300/월 | 월말 집중 사용, 평소 적은 사용량 |
| 운영팀 (4명) | $200/월 | 파일 정리 위주, 가벼운 사용 |

### 예산 관리 팁

- **첫 달은 넉넉하게** — 패턴 파악 전에 빡빡하게 잡으면 업무에 지장이 생긴다
- **월간 추이를 보고 재조정** — 1-2개월 데이터 수집 후 적정 한도를 재설정한다
- **특수 시기 고려** — 분기말, 연말 결산 시 임시 한도 상향을 검토한다
- **80% 알림 설정** — 한도에 근접하면 관리자에게 사전 알림이 오게 한다

## 사용량 모니터링

도입 후 실제로 얼마나, 어떻게 사용되고 있는지 파악해야 ROI를 측정하고 개선할 수 있다.

### 대시보드 (Admin Console)

Admin Console의 대시보드에서 확인할 수 있는 항목은 다음과 같다.

| 항목 | 설명 |
|------|------|
| 세션 수 | 특정 기간 동안 진행된 Cowork 세션 총 수 |
| 활성 사용자 수 | 실제로 Cowork를 사용한 인원 |
| 시간대별 분석 | 어느 시간대에 사용량이 집중되는지 |
| 그룹별 사용량 | 부서/그룹별 사용 현황 비교 |

### Analytics API

더 세밀한 분석이 필요하면 Analytics API를 활용한다. 프로그래밍 지식이 있는 IT 팀원이나 데이터 분석가가 활용하기 적합하다.

| 데이터 | 설명 |
|--------|------|
| 개인별 Cowork 활동 | 각 사용자의 세션 횟수, 사용 시간 |
| 스킬/커넥터 사용 현황 | 어떤 스킬과 커넥터가 가장 많이 쓰이는지 |
| DAU/WAU/MAU | 일간/주간/월간 활성 사용자 수 추이 |
| 통합 추적 | Chat, Claude Code, Cowork를 포함한 전체 사용 현황 |

### 모니터링 데이터 활용법

수집된 데이터를 아래 목적으로 활용한다.

| 목적 | 활용 방법 |
|------|-----------|
| **ROI 입증** | 도입 전후 작업 시간 비교, 비용 대비 절감 효과 산출 |
| **파워 유저 발굴** | 사용량 상위 10%를 찾아 내부 전파자로 활용 |
| **교육 기회 파악** | 사용량이 적은 팀을 식별해 추가 교육 제공 |
| **플랜 최적화** | 실제 사용 패턴에 맞춰 플랜을 업/다운그레이드 |
| **업무 패턴 분석** | 어떤 작업에 가장 많이 사용되는지 파악해 스킬/플러그인 우선순위 결정 |

## 보안 설정

조직 수준의 보안 요구사항을 충족하기 위한 설정 방법이다.

### OpenTelemetry 연동

Cowork의 활동 로그를 외부 보안 모니터링 도구로 전송할 수 있다. 이를 통해 기존 보안 인프라와 통합 관리가 가능하다.

| 추적 가능한 활동 | 설명 |
|-----------------|------|
| 도구(tool) 호출 | Claude가 어떤 도구를 사용했는지 |
| 커넥터 실행 | Gmail, Google Drive 등 외부 서비스 접근 기록 |
| 파일 작업 | 파일 읽기, 쓰기, 삭제, 이동 기록 |
| 스킬 사용 | 어떤 스킬이 실행되었는지 |

지원되는 수신 플랫폼은 다음과 같다.

- **Splunk** — 대규모 로그 분석 플랫폼
- **Cribl** — 데이터 라우팅 및 변환
- **기타 OpenTelemetry 호환 도구** — Datadog, New Relic 등

### 커넥터 세분화 제어

커넥터(외부 서비스 연결)를 사용할 때, 단순히 "허용/차단"이 아니라 세부 동작 단위로 제어할 수 있다.

| 커넥터 | 허용 가능한 세부 동작 예시 |
|--------|--------------------------|
| Gmail | 읽기만 허용, 발송 차단 |
| Google Drive | 읽기 허용, 쓰기/삭제 차단 |
| Slack | 메시지 읽기만, 발송 차단 |

이렇게 설정하면 Claude가 이메일을 읽어서 내용을 분석할 수는 있지만, 임의로 이메일을 보내는 것은 차단된다.

### AI 동작 승인 방식

Claude의 동작에 대한 승인 방식을 설정할 수 있다.

| 승인 방식 | 설명 | 적합한 상황 |
|-----------|------|------------|
| **자동 승인** | Claude가 스스로 판단하여 실행 | 위험도 낮은 작업 (파일 읽기, 요약) |
| **수동 승인** | 매번 사용자 확인 후 실행 | 위험도 높은 작업 (파일 수정, 외부 전송) |

관리자가 동작 유형별로 자동/수동을 지정할 수 있어, 일상적인 작업은 자동으로 진행하되 위험한 작업만 사용자 확인을 거치도록 설정할 수 있다.

## 팀 플러그인 배포

플러그인은 스킬(특정 작업 능력)과 커넥터(외부 서비스 연결)를 묶어 하나의 패키지로 만든 것이다. 관리자가 팀 전체에 표준화된 워크플로우를 배포할 수 있다.

### Marketplace 활용

Anthropic이 제공하는 Marketplace에서 검증된 플러그인을 설치할 수 있다.

1. Admin Console에서 Marketplace로 이동
2. 필요한 플러그인을 찾아 설치
3. 플러그인을 사용할 그룹을 지정
4. 사용자의 Cowork에 자동으로 배포

### 조직 관리 플러그인

관리자가 배포한 플러그인은 일반 사용자가 수정하거나 삭제할 수 없다. 이를 통해 조직 전체의 워크플로우 일관성을 유지할 수 있다.

| 구분 | 사용자 설치 플러그인 | 조직 관리 플러그인 |
|------|---------------------|-------------------|
| 설치 권한 | 개인 | 관리자만 |
| 수정 가능 | 사용자가 자유롭게 | 관리자만 수정 가능 |
| 삭제 가능 | 사용자가 삭제 가능 | 사용자 삭제 불가 |
| 적용 범위 | 개인 | 지정된 그룹 전체 |

### 그룹별 플러그인 배포

각 그룹(부서)에 필요한 플러그인만 배포할 수 있다.

```
마케팅팀: 콘텐츠 분석 플러그인 + 소셜 미디어 리포트 플러그인
재무팀:   재무 보고서 플러그인 + 데이터 검증 플러그인
운영팀:   파일 정리 플러그인 + 일정 관리 플러그인
```

### 팀 전용 커스텀 플러그인 만들기

Marketplace에 없는 업무 특화 워크플로우가 필요하다면, 스킬과 커넥터를 조합해 커스텀 플러그인을 만들 수 있다. 예를 들어 "주간 마케팅 리포트" 플러그인을 만들면 — Google Analytics에서 데이터를 수집하고, 차트를 생성하고, 보고서를 작성하고, Drive에 저장하는 과정을 하나의 패키지로 묶을 수 있다. 팀원 누구나 같은 품질의 보고서를 생성할 수 있게 된다.

## 단계별 도입 전략

Cowork를 조직에 도입할 때는 한꺼번에 전사 배포하는 것보다 단계적으로 확대하는 것이 안전하고 효과적이다.

### Phase 1: 시범 운영 (2주)

| 항목 | 내용 |
|------|------|
| **대상** | IT팀 또는 선도 사용자 5명 |
| **범위** | 기본 파일 작업 (정리, 이름 변경, 형식 변환) |
| **목표** | 도구 안정성 검증, 보안 정책 적합성 확인 |
| **성공 지표** | 참여자 전원이 3회 이상 작업 완료, 보안 이슈 없음 |
| **주요 활동** | 설치 가이드 작성, 기본 사용법 교육, 피드백 수집 |

**주요 이슈와 대응**: 설치 환경 차이, Global Instructions 미설정, 작업 폴더 미숙지가 흔하다. 설치 체크리스트와 Global Instructions 템플릿을 미리 준비한다.

### Phase 2: 부서별 확대 (4주)

| 항목 | 내용 |
|------|------|
| **대상** | 2-3개 부서의 파워 유저 (부서당 2-3명) |
| **범위** | 커넥터 연동 (Gmail, Drive 등), 스킬 커스터마이징 |
| **목표** | 실제 업무 적용 가능성 검증, ROI 측정 시작 |
| **성공 지표** | 주당 5회 이상 사용하는 파워 유저 3명 이상, 작업 시간 30% 이상 단축 |
| **주요 활동** | 부서별 사용 사례 발굴, RBAC 설정, 지출 한도 설정 |

**주요 이슈와 대응**: 커넥터 권한 혼란, 부서별 스킬 부재, 예산 초과가 흔하다. 부서별 권한 매트릭스를 사전에 작성하고, 첫 달은 지출 한도를 넉넉하게 설정한다.

### Phase 3: 전사 배포 (8주)

| 항목 | 내용 |
|------|------|
| **대상** | 전사 (Cowork가 필요한 모든 부서) |
| **범위** | 예약 작업, 플러그인 배포, 팀 표준 워크플로우 |
| **목표** | 조직 전체 생산성 향상, 표준화된 업무 프로세스 정착 |
| **성공 지표** | 월간 활성 사용률 70% 이상, 반복 업무 시간 50% 이상 단축 |
| **주요 활동** | 전사 교육, 커스텀 플러그인 배포, 모니터링 체계 구축 |

**주요 이슈와 대응**: 변화 저항, 교육 부족, 예약 작업 오류가 흔하다. 파워 유저를 부서별 내부 코치로 지정하고, 월 1회 활용 사례 공유 세션을 운영한다.

### 도입 타임라인 요약

```
Week 1-2   [Phase 1] IT팀 5명 시범
           ├── 설치, 기본 교육
           └── 보안 정책 검증

Week 3-6   [Phase 2] 부서별 파워 유저 확대
           ├── 커넥터 연동
           ├── RBAC + 지출 한도 설정
           └── ROI 측정 시작

Week 7-14  [Phase 3] 전사 배포
           ├── 전사 교육 + 가이드 배포
           ├── 예약 작업 + 플러그인
           └── 모니터링 체계 안정화
```

## 자주 묻는 질문

### "직원들의 파일이 Anthropic에 전송되나요?"

Cowork는 사용자의 컴퓨터에서 로컬로 실행된다. 파일 자체가 업로드되는 것은 아니지만, 대화 과정에서 파일 내용이 Claude 모델을 통해 처리된다. 대화 기록은 로컬 저장된다. 민감 데이터 처리 시 [안전하게 사용하기](07-안전하게-사용하기.md)를 참고한다.

### "기존 보안 정책과 충돌하지 않나요?"

Cowork는 폴더 기반 격리 구조를 사용한다. 공유한 폴더의 파일만 접근 가능하고, OpenTelemetry 연동으로 기존 보안 시스템(Splunk 등)과 통합할 수 있다. 도입 전 IT 보안팀과 접근 폴더 범위, 모니터링 보존 기간, 커넥터별 허용 동작을 검토한다.

### "사용량이 갑자기 늘어나면?"

그룹 지출 한도를 설정해두면 한도 도달 시 사용이 자동 중단되어 비용 폭증을 막을 수 있다. 초기에는 넉넉하게 설정하고, 1-2개월 후 실제 패턴에 맞춰 재조정한다.

### "규제 대상 업무에 사용해도 되나요?"

현재 Cowork 활동은 Audit Log, Compliance API, Data Exports에 포함되지 않는다. 금융, 의료, 법률 등 기록 의무가 있는 규제 워크로드에는 사용하지 않는다. 일반 업무에 먼저 활용하고, 규제 지원이 추가되면 범위를 확대한다.

### "도입 효과를 어떻게 측정하나요?"

아래 지표를 도입 전후로 비교한다.

| 지표 | 측정 방법 |
|------|-----------|
| 작업 소요 시간 | 주요 반복 작업 5개를 선정하여 전후 시간 비교 |
| 활성 사용률 | Analytics API의 MAU / 전체 라이선스 수 |
| 사용자 만족도 | 월 1회 간단한 설문 (1-5점 척도) |
| 비용 효율 | 월간 구독료 / 절감된 업무 시간의 인건비 환산 |

## 핵심 정리

- 반복적인 문서 작업, 데이터 추출, 보고서 생성이 많은 팀일수록 Cowork 도입 효과가 크다.
- 플랜은 팀 규모와 용도에 맞게 선택한다. 5명 이하 시범은 개인 Pro, 본격 도입은 Team Premium 이상을 권장한다.
- RBAC로 부서별 기능 접근을 제어하고, 그룹 지출 한도로 예산을 관리한다.
- OpenTelemetry 연동으로 기존 보안 인프라와 통합할 수 있다.
- 도입은 3단계(시범 → 부서 확대 → 전사 배포)로 진행한다. 2주 → 4주 → 8주가 권장 일정이다.
- Cowork 활동은 현재 Audit Log에 포함되지 않으므로, 규제 워크로드에는 사용하지 않는다.
